# Subscription baseline export

`scripts/subscription_baseline.py` combines a saved strict task attribution result with explicit, sanitized account meter observations. It reads local files only and writes JSON to standard output; it does not inspect live accounts or infer subscription allowance from tokens or API-equivalent cost.

```bash
python3 scripts/profile.py --task-manifest /private/cohort.json --json > /private/attribution.json
python3 scripts/subscription_baseline.py \
  --attribution /private/attribution.json \
  --windows /private/windows.json > /private/baseline.json
```

`windows.json` is an array with one record per enrollment/provider/account scope. For a task that uses both Codex and Claude, supply separate records with the same `enrollment_id` and their respective `provider` and opaque `account_key`. Each record needs `task_start`, `task_end`, `before` and `after` observations, and interval isolation evidence. Both observations carry the same provider/account key, an `observed_at` time, and `five_hour` and `seven_day` objects with `utilization` (fraction from 0 to 1) and `reset_at` (ISO timestamp). Capture them within five minutes of the task boundaries. The isolation object carries the same provider/account key, `from`, `until`, `coverage: "complete"`, `other_work_count: 0`, a nonempty `source`, and `evidence_refs`; its interval must cover both observations. A boundary `inFlight: 0` reading is insufficient. Keep raw account identifiers and emails out of the input and output.

The exporter preserves strict collector request totals, cache reads and writes, and reasoning output as a subset of output. `total_work` includes every bound request, including retries and cohort shared work; the `cohort_shared` subtotal makes that difference visible. Per-task usage includes the task's bound attempts and review. The result also carries `evidence_mode`, `coordinator_coverage`, and a sanitized `evidence_exclusions` summary with only reason and request count. An observation for an enrollment absent from the strict result is rejected. `accepted` comes only from independently verified acceptance in the strict result. `model_identities` lists models observed in valid native request evidence. `effort` and `tier` remain null because the strict request records do not establish them; the exporter does not fill them from defaults. Each `provider_quotas` entry has a provider request count and its own quota result. A task that spans providers has an unknown task-level `quota` because provider percentages cannot be added. Multiple accounts for one provider yield an unknown provider quota because request-to-account binding is absent. An incomplete strict result, account switch, meter reset (including a same reset timestamp that is not strictly later than the after observation), stale observation, invalid delta, missing interval isolation, concurrent work, or missing provider observation yields unknown deltas.

Even a well-formed isolation record is supplied evidence, not host-verified proof. Its `source` must be present for validation but is never echoed in output. The exporter labels resulting meter deltas `asserted_unverified`; it makes no claim of an accepted task's actual quota cost. A future host evidence verifier would be needed before that status could be promoted. Five-hour and weekly percentage changes are separate observations, not a conversion from token counts or API prices.
